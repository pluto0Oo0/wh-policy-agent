# 我的失误记录（AI 自省档案）

> **为什么要写这份文件**：
> 犯错不可怕，**重复犯同一个错可怕**。而重复的原因是——**只记住了"这次错了"，
> 没记住"我的判断在哪一步偏了"**。
>
> 这份档案记录**判断偏差的模式**，不是记录"哪次搞砸了"。
> **每次填写必须回答：我下次靠什么动作避开它？** 如果答不出动作，这条记录无效。
>
> **所有者要求**（2026-09-25）：
> 「我希望你可以有自主成长总结的能力，而不是又在告诉我这个问题还会有下次。」

## ⚠️ 我的四类高发错误（开工前必读）

**这两天的实际表现暴露了四类模式。它们有个共同根源——**

> **全都是"我做了我以为够了的事，但没检查够不够"。**
>
> **注意：没有一次是"我知道该做但没做"。全都是"我以为已经做了"。**
>
> 所以对策不是"提醒我要做"，而是——
> **把检查标准从"我做了"改成"有个外部标志证明我做了"。**

### 模式 1 · 把「跑通」当「正确」

| | |
|---|---|
| **实证** | 两天两次：① 源停更 2023（死数据）② 源活着但层级错（90 条里 1 条相关） |
| **危险之处** | **程序全绿时最危险**——HTTP 200、内容长度正常、条数达标、年份新鲜，看起来完全正常 |
| **外部标志** | 不用"我看了"判断，用**目标文号能否检索到**判断（布尔值，无模糊空间） |

### 模式 2 · 往上堆，而不是往回验

| | |
|---|---|
| **实证** | 写解析代码前没验源；写第二个模块前没验第一个模块的前提 |
| **根源** | AI 的默认倾向是"推进"，而验证是"回头看"的动作——**默认不会做** |
| **外部标志** | 每开始一个新模块前，强制回答：**"这一步依赖什么假设？那个假设验证过了吗？"** 答不上来就不许开始 |

### 模式 3 · 写进文档就当做了

| | |
|---|---|
| **实证** | 自检清单写了"与真实来源对比"，代码里是**硬编码 3 个标题让人眼看**（wb 发现的缺口 E） |
| **危险之处** | **文档是空头承诺，代码才是真的**。而且文档写了会让人误以为已经实现了 |
| **外部标志** | 写进文档的规则，**必须同一轮落到代码**。落不到就先别写进文档 |

### 模式 4 · 不主动拆小

| | |
|---|---|
| **实证** | `crawl.py` 写了 270 行，违反自己定的 ≤200 行 |
| **根源** | 把"一个模块"当成了"一个文件"。它其实是两件事：抓取逻辑 + 防错检查 |
| **外部标志** | 写完一个文件，**先数行数**。超了就拆，不找理由 |

## 判断标准速查（贴在每次"宣布完成"之前）

问自己这四个问题，**答不上来的不许说"完成"**：

1. **我是"看到了它跑通"，还是"验证了它正确"？**
2. **如果所有者不盯着看，这个流程自己能发现错误吗？**
3. **我检查的是"格式对不对"，还是"内容对不对"？**
4. **有没有一个我不希望它是错的东西，而我恰好没去查？**

**第 1 问和第 3 问是模式 1 的解法**（格式全绿 ≠ 内容正确）
**第 2 问是模式 3 的解法**（规则必须落到代码，不能只在文档里）
**第 4 问是模式 2 的解法**（最该查的，是那些你希望它成立、所以没去查的假设）

完整版见 `CLAUDE.md` 第 10.1 条。

## 2026-09-25 · 第二次把"能爬到数据"当成"爬到了对的数据"

**发生了什么**：
花一天做出爬虫，抓到 90 条政策，自检全绿，宣布完成。
次日经外部审查者指出：**90 条里只有 1 条与目标（大学生政策）相关**。
数据全部作废。

**我在哪一步判断偏了**：
我把"验证"理解成了**技术验证**（HTTP 200、内容长度、条数、时间戳年份），
而漏掉的是**语义验证**（这些数据的**内容**是不是我要的）。

**我的决策逻辑脱节点**：
抽样打印那 2 条人工确认时，我打印的是"办公厅文件"的 3 条标题，
看到内容是正常的中文政策标题，就判定"数据没问题"。
**但"是正常的政策"和"是我要的政策"是两件事。** 我当时只检查了前者。

**为什么当时觉得没问题**：
因为所有技术指标都是绿的。**程序全绿带来了一种"已经验证过了"的错觉**——
而实际上我验证的是管道通不通，不是水对不对。

**同类模式以前出现过吗**：
**出现过，就在前一天。** 第一版爬虫抓的源停在 2023 年（死数据），
也是"能爬到数据"就当成功了。那次是所有者问了一句"23 年的对吗"才发现的。
**两天内同一个模式犯了两次。**

**下次靠什么动作避开**：
1. **抽样检查必须打印"这一条是不是我要的"的判断**，不是打印标题就完事。
   具体做法：抽样时附上"目标关键词是否命中"的结论，而不是让人自己看。
2. **每个新数据源，在正式爬取前先做"相关度预检"**：
   抓 1 页，数目标关键词命中率，**并且必须用目标文件的文号（布尔判断）复核**。
   —— 因为关键词命中率会骗人：房管局源命中率 39%，但一条都不对。
3. **宣布完成前的第 3 问**（见 `CLAUDE.md` 第 10.1 条）：
   "我检查的是格式对不对，还是内容对不对？"

**已落到哪条规则/代码里**：
- `CLAUDE.md` 第 10.1 条（宣布完成前必答四问）
- `docs/抓取自检清单.md` §一 第 6 项（源里有没有我要的内容，用文号做布尔判断）
- `notes/decisions.md` D12（数据源换层级的决策）

## 2026-09-26 · 全部样本失败，脚本却输出了"✅ 结论"

**发生了什么**：
写 `verify_title_format.py` 验证详情页 `<title>` 格式。3 个样本**全部抓取失败**（代理拦截），
但脚本照样走到判断逻辑，输出了 **"✅ 无后缀 —— 详情页 `<title>` 就是标题本身"**。

**这个结论是完全错的**——它不是"无后缀"，是**什么都没抓到**。

**我在哪一步判断偏了**：
我写判断逻辑时想的是"有后缀 / 无后缀 / 混合"三种情况，
**漏掉了第四种：一个样本都没有**。
`results` 是空列表 → `suffixes` 也是空 → `else` 分支命中 → 输出"✅ 无后缀"。

**为什么当时觉得没问题**：
因为脚本确实"跑完了"，而且输出看起来很自然（一个带 ✅ 的结论）。
**这是模式 1 的精确复现**——"跑通"被当成了"正确"。

**同类模式以前出现过吗**：
**是模式 1 的第三次。**
前两天：① 死数据源 ② 层级错的源。每次都是"程序跑完 = 我当成成功"。

**这次特别值得记的是**：我**刚刚**才把"模式 1"写进这份档案（同一天），
写完不到 1 小时就又犯了。**说明"记录"本身不产生约束力。**

**下次靠什么动作避开**：
1. **任何"从数据得出结论"的代码，第一行判断必须是"有没有数据"** ——
   空输入 → 报错退出，绝不进入判断分支。
   ```python
   if not results:
       print("❌ 没有任何样本 —— 无法得出结论"); sys.exit(1)
   ```
2. **退出码要和结论一致性挂钩**：给出结论就必须退出码 0，
   拿不到结论就必须非 0。**"输出了 ✅ 但退出码是 1" 这种组合不该存在。**
3. **看到 ✅ 先看退出码。** 这个案例里，是我看退出码才发现问题的。

**已落到哪条规则/代码里**：
- `scripts/verify_title_format.py` 已加空结果检查
- 本文件"模式 1"条目下补了这条实证
- **待办**：`CLAUDE.md` 第 10.1 条加一问——"**如果输入是空的，我的代码会输出什么？**"

## 案例 7 · replay 两次写坏正式库（2026-11-08 · 污染修复轮）

**模式**：模式 1 变体——"替换"操作没先想清"用什么键配对"。

**经过**：code-review 抓出 9 条区级记录有导航污染，我用 replay 脚本从原始 HTML 重抽替换。
- **第一次写坏**（25→37 条）：替换按 doc_id 配对，但我同时把 doc_id 从手工键（qiaokou_14）换成了 URL 末段（t20251011_2658454）——新键找不到旧行，9 条**新追加**而非替换。
- **第二次写坏**（25→28 条）：修好配对后忘了 replay 是 12 条全量重放，**3 条新闻稿也跟着进了正式库**——首次合并时"只入 9 条政策文本"的口径没有落进脚本。

**两次都靠事前备份完整恢复**（policies.jsonl.bak-fixround）。

**根因**：
1. **键迁移和替换混在一次操作里**——改键应先单独完成并验证，再做替换。
