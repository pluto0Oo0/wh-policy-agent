## 二、3 个精度问题（不阻断，记进 CONTEXT §13）

### 问题 1 · `_03`/`_04` 输出重复

两条都显示"取得普通高校…全日制大专以上学历"。**用户会困惑"重复了"。**

**改进**：CLI 输出区分维度——"✅ 学习形式：全日制" / "✅ 学历层次：本科以上"。
**时机**：扩语料前顺手改，成本约 5 行。

### 问题 2 · `_05`/`_07` source_text 几乎一样

```
✅ 本通知公布之日起在汉就业创业并正常缴纳社会保险   ← _05 PASS
❓ 在汉就业创业并正常缴纳社会保险                    ← _07 UNKNOWN
```

**用户会问"第 5 条过了第 7 条为什么判不了"。**

**根因**：同一句原文被标了两条条件，source_text 几乎一样。**这是 wb 预标注草案的设计问题**——_05 的 source_text 应该只取"本通知公布之日起"。
**时机**：扩语料时改进标注规则。

### 问题 3 · amount type="onetime" 会误导用户

39600 是 3 年累计减免，不是"一次性"补贴。**type=onetime + value=39600 会让用户以为是"一次性补贴 39600 元"**——实际是 3 年每月省一些。**不只是"不够准确"，是会误导用户做财务规划。**

**改进**：Phase 2 前加 `cumulative` 类型，detail 里同时给月省额拆解。
**时机**：Phase 2 前置。

### 问题 4 · ⚠️ 豁免标注原因不准（复查发现，最该修）

**实测**：`data/profile.json` 的 `age=23` + `education="本科"`。
- age=23 < 45 → **直接 PASS**（不需要豁免）
- education="本科" → exempt_when（education in {硕士,博士}）**不成立**

**但 CLI 输出标了"← 因豁免而满足"**——23 岁本科生靠的是年龄 < 45 正常通过，不是豁免。

**根因推测**：CC 的判定逻辑是"exempt_when 字段存在就标 exempted"，**不管豁免是否实际触发了**。

**更深的隐患**：如果 CLI 总是标"因豁免"，**豁免机制是否真的生效就测不出来了**——不管触发没触发都标"因豁免"，是"永远不报警的检查 == 没检查"的变体。

**改进**：CLI 只在**正常判定会 FAIL 但豁免让它 PASS** 时标"因豁免而满足"。正常判定也会 PASS 时标"因符合"。
**时机**：扩语料前修——这是用户可见的输出问题，面试演示时会被追问。
**优先级提升到 P1**。
