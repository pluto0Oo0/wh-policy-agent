### 0.1 秋招已经错过了，这是既定事实

2027 届秋招是 2026 年 9-11 月，**现在正在高峰里**。你手上没有能投的东西。

**不纠结，往后看。**

### 0.2 你真正的窗口

| 时间 | 事件 |
|---|---|
| 2026-12 ~ 2027-01 | **开始投递**（日常实习可随时入职） |

| 2027-02 ~ 2027-06 | 大四下，课少，**可全职实习 4-5 个月** |

→ **你大四下能做满 4-5 个月，这个条件比很多竞争者好。**

## 2. P0 · 补基础（第 1-3 周）

**为什么单独拿出来**：你的短板是「读代码」，不是「写代码」。
**所以这三周不是学语法，是学"看懂别人写的代码"。**

| 周 | 做什么 | 产出 |
|---|---|---|
| 1 | 装 Python 3.11 + VS Code + Git；建仓库；跑通第一个 HTTP 请求 | 环境能跑 |
| 2 | **读一段真实代码并逐行讲解**（用第 1 周自己写的请求代码）；理解：变量/循环/函数/异常 | 能解释自己的代码 |
| 3 | 写第一个真实模块：**爬一个市级政策列表页**，存成 JSON | 爬虫 v0 |

**关键方法**：**不要看教程，用真实任务学。**
每个知识点都在"我要爬这个页面"的语境里出现，比抽象例子记得牢。

**P0 出关标准**（硬指标，不达标不往下走）：
- [ ] 能对着自己写的 20 行代码，逐行说出"这行做什么、为什么这么写"
- [ ] 遇到报错能自己定位到行，并说出大致原因

## 3. P1 · 判定闭环（第 4-13 周）

**范围**：安居/住房垂直，30-40 条政策，**纯 Python，不含 LLM**。

| 周 | 模块 | 内容 | 验收 |
|---|---|---|---|
| 4 | 脚手架 + `crawl.py` | 市级专题页 + 武汉人才工作网接口 | 抓到 ≥10 条 |
| 5 | `crawl.py` 完成 | 加 2 个 SPA 接口 + 区级静态页 + 幂等 + sleep(1) | 抓到 ≥30 条 |
| 6 | `clean.py` | 清洗 + 模板族识别（A-G） | 每条带 template_family |
| 7 | `parse.py` | 七段式字段切分，按模板族分支 | 能切出"申报对象及条件"段 |
| **8-10** | **人工标注** | `golden_conditions.jsonl`，30-40 条政策 | **≥150 条条件，每条带 source_text** |
| 11 | `conditions/` + `cohort.py` | 数据模型 + **人群分层** | 能区分 2022-06-07 前后 |
| 12 | `eligibility.py` | 规则判定（含 UNKNOWN 分支） | 3 个画像能出结果 |
| 13 | `calc.py` + `cli.py` + `evaluate.py` | 金额计算 + 命令行 + 评测 | **跑出准确率数字** |

> ⚠️ **第 8-10 周的人工标注不能压缩。** 这是全项目最"脏"的活，但也是简历上"**我人工标注了 150 条条件**"这句话的来源。调研报告 §11.4 原话："**评测问题一定要来自真实用户**"。

**P1 验收**（SPEC §6 的三条命令全绿）：

```bash
python scripts/build_data.py          # ≥30 行 policies.jsonl
python -m src.cli ask --profile data/profile.json
python scripts/evaluate.py            # 三类 verdict 准确率
```

## 4. P2 · LLM 条件抽取（第 14-17 周）

| 周 | 内容 |
|---|---|
| 14 | LLM 抽取 + **schema 强约束**（可判定的事不交给模型） |
| 15 | 失败重试 + 抽不出降级人工 |
| 16 | **A/B 对比**：LLM 抽取 vs 第 8-10 周的人工标注 |
| 17 | 写进 `reports/`，更新 README |

**为什么这段值钱**：调研报告 §11.1 给出行业抽取准确率上限 **82%**（5 家平台实测）。
**你手上有人工标注的 ground truth，所以能测出自己的真实数字。** 这是天然的 A/B 实验，别人做不了。

**面试话术**：
> "我先人工标了 150 条条件做基线，再上 LLM 抽取对比。人工基线 100%，LLM 抽到 X%。差距集中在模糊表述上——'积极求职创业'这种，模型会硬给一个解释，而正确做法是返回 UNKNOWN。"

| 周 | 内容 |

**这是全项目最有区分度的部分。** 调研报告 §7.5 原话——官方审计机关自己承认：

> "**相关条文相互矛盾、掣肘甚至打架**"

**这句话可以直接写进 README。** 你处置的不是 bug，是被审计机关正式记录过的行业难题。

## 6. 贯穿全程的三件事

### 6.1 每周一次"讲给活人听"

**不要等到面试前才练。** 每周找同学讲 10 分钟本周做的东西，让他随便追问。

**为什么**：调研报告实测的识破路径是「**沿一个细节连续追问 3-4 层**」。
自己练发现不了第 3 层的问题，活人能。

### 6.2 每个技术决策当场记进 `notes/decisions.md`

格式：**结论 + 为什么不选另一个 + 代价是什么**。

**这是面试唯一真正的考点。** 攒到面试前回忆，一定漏。

### 6.3 找真实用户（第 13 周前完成）

**目标：20 个 2026 届学长学姐。**

调研报告 §8 的措辞建议（直接用，是真的）：

> "我给 N 个 2026 届学长学姐跑过，命中 X 条，其中 Y 条我去核实发现官方自己写着两个不同口径。"

**这是简历上最难被替代的一句话。** 它同时证明：接触过真实用户 + 核对过官方矛盾。

## 7. 风险与砍单顺序

| 风险 | 预案 |
|---|---|
| 工期不够 | **砍 P3 → 砍 P2 → 减少政策条数**。P1 一个都不能砍 |
| 人工标注超时 | 政策条数从 40 降到 25，但**不能跳** |
| 找不到学长学姐 | 退而求其次：学校就业指导中心、班级群、学院公众号 |
| 抽取准确率不达标 | **如实报告，不美化**。报告里那个 82% 上限就是你的参照 |
| 某周完全没进度 | 不补，直接进下一周。**宁可少做，不可积压** |

### 保底交付

**能跑的判定闭环 + 30 条政策 + 50 条评测集 + 准确率数字 + README。**

**哪怕只做到第 12 周，也已经有一个能演示、能讲的项目。** 比"还在学 Python"强得多。
