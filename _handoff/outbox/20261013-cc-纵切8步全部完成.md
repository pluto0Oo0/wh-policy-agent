## 三、🔴 我在写 CLI 时犯了两个 bug，都属"输出误导用户"

### Bug 1 · 把「用户能补的」说成「不是你的事」

CLI 原来把所有 `status_detail` 都当成引擎层问题，于是输出：

```
· （这条不是你能补的）缺 market_rent（市场租金需用户提供）
```

**自相矛盾**：括号里说"不是你能补的"，内容却说"市场租金需**用户**提供"。

**根因**：我把 `status_detail` 当成了"引擎短板"的统一出口，
但它在 `_09` 那里装的是"缺输入字段"—— **那是用户能补的**。

**修法**：**缺输入字段走 `missing_fields`**（用户能补的走统一路径），
`status_detail` **只留给引擎短板**（形态不认识那种）。
→ 输出变成「请补充：你租的房子月租金（元）」✅

### Bug 2 · 把内部字段名抛给用户

CLI 原来用 `cond.field` 生成追问，而 `_09`（计算类）的 `field` 是**输出字段** `rent`：

```
· 请补充：rent          ← 用户根本不知道那是什么
```

**修法**：改用 `missing_fields`（**引擎给的权威清单**）+ 一张 `FIELD_LABELS` 映射表
（`market_rent` → 「你租的房子月租金（元）」）。

**为什么用 missing_fields 而不是 cond.field**：计算类条件的 `field` 是**输出**，
缺的**输入**只在 `missing_fields` 里。**这个区别在写 CLI 之前没暴露过。**
