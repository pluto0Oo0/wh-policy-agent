## 二、四个关键判断（请所有者重点看）

### 1. 不是 89 条全塞进 golden（这是最重要的）

机械做法是"52 条独立条全转 Condition"。**没有这么做**，因为草案里大量条目是：

- `rent == "市场价"`（延长期租金条款）——不是资格条件；
- `qualification_valid <= "延长2年"`——权益期限；
- `rent == "3.8元/㎡·月"`——**房源定价（产品信息）**；
- `qualification_valid == False`——"不再符合条件应退出"——退出条款。

这些塞进 v4 会让每条区级政策**永远 UNKNOWN**（计算类算不出 → UNKNOWN），
把准确率数字变成噪声。**所以只转 27 条真正可判定的资格/材料/时序条件。**

### 2. Codex 草案重复发明了一个已有字段

草案建议新增 `household_registration_in_wuhan`（2 条：洪山 FAQ、汉阳解读），
**画像里已有 `hukou_wuhan`**（v3 就在用）。两条都已映射到既有字段，**不新增**。

> 教训：起草新字段前先全文搜 `FIELD_DOMAINS`，否则会把已有字段重复发明一遍。

### 3. 覆盖完整性是从 pending 反推的，不是拍脑袋

48 条挂起里出现过的 doc_id = 覆盖不完整。**11 个不完整政策不能拿来算准确率**——
少了「意向租住区」字段，硚口公告会把江岸的人判成符合，**假 ELIGIBLE 且输出完全正常**。
T05 因此规定：`evaluate.py` 默认只评 8 个完整政策。

### 4. code-review 抓到一个引擎级假阳性，已修

**当一条政策的全部条件都是 N/A 时，`check_eligibility` 原来返回 ELIGIBLE**
（自测断言⑧明确写了这个行为）。v4 让它变得可达：
汉阳解读的 3 条全是老政策通道，新轨道画像去看 → 全部 N/A → 被判「✅ 符合」。
**已改为 UNKNOWN + 明确警告**（`status_warning="该政策的全部条件都不适用于你的政策轨道"`），
自测断言⑧也改成要求 UNKNOWN。这是**判定语义变更**，已写进本轮报告，等所有者确认。

另外加了 **CLI 覆盖完整性护栏**：政策在 `eval/v4_pending.jsonl` 里有未结构化条件时，
结论显示为「❓ 信息不足（还有 N 条条件未结构化）」，不再显示"✅ 符合"。
复查用 code-review 给的复现：`--policy t20251011_2658454` → 现在会打印覆盖警告。
