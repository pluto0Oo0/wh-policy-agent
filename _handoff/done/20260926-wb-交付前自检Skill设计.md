## 零、纠正我上一轮的错误

我 2026-09-26 说过「skill 治不了 CC 的病，因为 skill 是 WorkBuddy 的机制，CC 不会加载」。

**这句话是错的。** 查证结果：

1. **Agent Skills 开放标准最初就是 Anthropic 开发的**（2025-10-16 首发于 Claude Code，2025-12-18 发布为开放标准 `agentskills.io`）
2. Claude Code 原生支持 Skills，目录为 `.claude/skills/<name>/SKILL.md`（项目级）/ `~/.claude/skills/`（个人级）
3. 到 2026-04 已有 **20+ AI 产品采纳**该标准：Claude Code、OpenClaw、Codex CLI、Cursor、Gemini CLI 等
4. **同一份 SKILL.md 可以在这些产品上通用**

**→ 结论反转：做一份 Skill，wb 和 CC 都能用。这比分开做两个东西划算得多。**

Claude Code 相对标准的三个扩展能力，其中第三条是本方案的核心：
- invocation control（谁能调用）
- subagent execution
- **dynamic context injection**：`!命令` 语法，Claude Code 会先执行命令、把输出替换进 skill 内容，**再**交给模型。这让 skill 能从「提醒 AI 去检查」升级成「把检查结果摆在 AI 面前」。

**→ 这是治「CC 写完不审查」的关键：不靠它自觉，靠机制在它宣布完成前把结果怼到它脸上。**

## 第 1 步：跑自动检查（必须先做）

```bash
python scripts/check_deliver.py
```

> 下面的 `!` 是 dynamic context injection：Claude Code 会先执行它、把输出插进来，
> 你看见的就是**真实的检查结果**，不是你自己推测的。

当前检查结果：

!`python scripts/check_deliver.py 2>&1`

**退出码非 0 就是没通过。不许跳过，不许说"这些问题不影响"。
修完重跑，直到退出码 0。**

## 第 2 步：脚本查不了的部分（人工核对）

脚本只能查可枚举的问题。下面三条必须你自己看，逐条回答：

1. **这批数据/这个模块，目的达到了吗？**
   （例：抓的政策列表，里面到底有几条是目标政策？——必须真的去数，不能"看起来有"）
2. **如果某条检查失败了，失败原因是什么？**
   ⚠️ **布尔判断会骗人**：`文号检索 = 0 命中` 有两种完全不同的原因——
   (a) 源不对 (b) **翻页不够**。2026-09-26 实测就踩过：78 号文其实在 `bgtwj` 第 10 页。
   **查失败原因，不要只看失败与否。**
3. **有没有"和常识不太一样"的地方，但脚本没报警？**
   有就列出来，哪怕不确定。**不确定的地方往往藏着真问题。**

## 第 3 步：输出格式

跑完必须输出三件事：
1. `check_deliver.py` 的完整输出（不截断）
2. 第 2 步三个问题的逐条回答
3. 本次**新增的检查项**——如果这次踩了新坑，把它加进 `scripts/check_deliver.py`，
   **不要只写进 markdown 文档**。文档里的规则会被忘，脚本不会。

## 本项目的专项红线

- 数据源：**先看有没有我要的内容，再看新不新，最后才看好不好爬**（顺序不能反）
- 政策数据：**必须区分「现行有效」和「只是旧」**——前者要核实，后者不构成风险
- 爬虫：0 条、条数异常、内容长度异常 → **报错**，不许静默返回空
- 单个文件 ≤200 行；禁 `except: pass`；所有文件读写显式 `encoding="utf-8"`

## 三、`scripts/check_deliver.py` 完整内容

```python
"""交付前自检 —— 把可枚举的检查全做掉。

用法：
    python scripts/check_deliver.py

退出码：0 = 通过；非 0 = 有检查项未通过（**此时不得宣布完成**）

设计原则：
    1. 只在真正出问题的时候报错，不做风格建议
    2. 每项失败都打印「为什么这条重要」，而不是只打印失败
    3. 宁可多报，不可漏报
"""

from __future__ import annotations

import ast
import json
import re
import subprocess
import sys
from pathlib import Path

PROJECT_ROOT = Path(__file__).resolve().parents[1]

# ── 阈值（改这里，不要改代码）──────────────────────────────
MAX_FILE_LINES = 200          # CLAUDE.md 第 2 条
MAX_FIELD_EMPTY_RATE = 0.20   # 自检清单 §二 第 3 条
MIN_EXPECTED_SAMPLES = 1      # expected_samples.json 至少要有一条，否则等于没检查
TARGET_DOC_NUMBERS = [        # 数据源验收硬指标（decisions.md D12）
    "武政办〔2022〕78号",
    "武房规〔2018〕2号",
]

SUSPECT_MOJIBAKE = ["锛", "銆", "鍏", "姘", "甯", "鏀", "锟斤拷"]

problems: list[str] = []
warnings: list[str] = []


def fail(msg: str) -> None:
    problems.append(msg)


def warn(msg: str) -> None:
    warnings.append(msg)


def changed_py_files() -> list[Path]:
    """本次改动/新增的 py 文件。取不到 git 信息时退化为扫描全项目。"""
    try:
        out = subprocess.run(
            ["git", "diff", "--name-only", "HEAD"],
            cwd=PROJECT_ROOT, capture_output=True, text=True, timeout=15,
        )
        names = [n for n in out.stdout.splitlines() if n.endswith(".py")]
        untracked = subprocess.run(
            ["git", "ls-files", "--others", "--exclude-standard"],
            cwd=PROJECT_ROOT, capture_output=True, text=True, timeout=15,
        )
        names += [n for n in untracked.stdout.splitlines() if n.endswith(".py")]
    except Exception:
        names = []
    if not names:
        names = [str(p.relative_to(PROJECT_ROOT))
                 for p in PROJECT_ROOT.rglob("*.py") if ".venv" not in p.parts]
    return [PROJECT_ROOT / n for n in names if (PROJECT_ROOT / n).exists()]


# ── 检查 1：单文件行数 ────────────────────────────────────
def check_file_length() -> None:
    for p in changed_py_files():
        n = len(p.read_text(encoding="utf-8", errors="replace").splitlines())
        if n > MAX_FILE_LINES:
            fail(f"[行数] {p.name} 有 {n} 行，超过 {MAX_FILE_LINES} 上限"
                 f"（CLAUDE.md 第 2 条）。超了不会报错，但所有者读不过来，审码会变成走过场。")


# ── 检查 2：静默吞错 ──────────────────────────────────────
def check_silent_except() -> None:
    for p in changed_py_files():
        src = p.read_text(encoding="utf-8", errors="replace")
        for m in re.finditer(r"except[^\n:]*:\s*\n\s*pass\b", src):
            line = src[: m.start()].count("\n") + 1
            fail(f"[静默吞错] {p.name}:{line} 出现 `except: pass`。"
                 f"这条会让所有错误消失得无声无息，是本项目最严重的反模式。")


# ── 检查 3：文件读写未显式指定编码 ────────────────────────
def check_encoding() -> None:
    for p in changed_py_files():
        src = p.read_text(encoding="utf-8", errors="replace")
        for m in re.finditer(r"\.(read_text|write_text|open)\s*\(([^)]*)\)", src):
            call = m.group(0)
            if call.startswith(".open") and "encoding" in call:
                continue
            if call.startswith((".read_text", ".write_text")) and "encoding" in call:
                continue
            if "encoding" in call:
                continue
            line = src[: m.start()].count("\n") + 1
            warn(f"[编码] {p.name}:{line} 文件读写未显式 encoding='utf-8'，Windows 上可能出乱码。")


# ── 检查 4：JSONL 数据完整性 ──────────────────────────────
def check_jsonl() -> None:
    for p in sorted((PROJECT_ROOT / "data" / "processed").rglob("*.jsonl")):
        raw = p.read_bytes()
        if raw[:3] == b"\xef\xbb\xbf":
            fail(f"[编码] {p.name} 带 UTF-8 BOM，部分工具解析会失败。")

        text = raw.decode("utf-8", errors="replace")
        lines = [ln for ln in text.splitlines() if ln.strip()]
        records, bad = [], 0
        for i, ln in enumerate(lines, 1):
            try:
                records.append(json.loads(ln))
            except json.JSONDecodeError:
                bad += 1
                if bad <= 3:
                    fail(f"[JSON] {p.name} 第 {i} 行解析失败。")
        if bad:
            continue

        # 乱码
        moji = sum(1 for r in records
                   if any(s in json.dumps(r, ensure_ascii=False) for s in SUSPECT_MOJIBAKE))
        if moji:
            fail(f"[乱码] {p.name} 有 {moji} 条含乱码特征字符。")

        # 空字段率
        if records:
            keys = set().union(*(set(r) for r in records))
            for k in keys:
                empty = sum(1 for r in records if not r.get(k))
                if empty / len(records) > MAX_FIELD_EMPTY_RATE:
                    fail(f"[空字段] {p.name} 字段 `{k}` 空值率 "
                         f"{empty}/{len(records)}，超过 {MAX_FIELD_EMPTY_RATE:.0%} 阈值。")

        # 去重：不能只按 url
        urls = [r.get("url") for r in records if r.get("url")]
        if len(urls) != len(set(urls)):
            fail(f"[重复] {p.name} url 有重复 {len(urls) - len(set(urls))} 条。")
        titles = [r.get("title") for r in records if r.get("title")]
        dup_titles = {t for t in titles if titles.count(t) > 1}
        if dup_titles:
            warn(f"[重复] {p.name} 标题重复 {len(dup_titles)} 个"
                 f"（同名不同文件可能正常，也可能是同一政策被两个栏目收录）："
                 f"{list(dup_titles)[:2]}")


# ── 检查 5：expected_samples 是否为真对比 ─────────────────
def check_expected_samples() -> None:
    """自检清单 §五 说「第 5 步最重要：和'应该是什么'对比」。
    若 expected_samples 文件不存在或为空，那这一步就是假的。"""
    path = PROJECT_ROOT / "eval" / "expected_samples.json"
    if not path.exists():
        fail("[假对比] 缺 eval/expected_samples.json。"
             "`data` 校验目前只能证明格式没坏，无法证明内容对了。参见 wb 缺口 E。")
        return
    try:
        data = json.loads(path.read_text(encoding="utf-8"))
    except json.JSONDecodeError as e:
        fail(f"[假对比] expected_samples.json 解析失败：{e}")
        return
    if len(data) < MIN_EXPECTED_SAMPLES:
        fail(f"[假对比] expected_samples.json 只有 {len(data)} 条，等于没做对比。")


# ── 检查 6：SPEC 声明的函数是否真的实现了 ─────────────────
def check_spec_signatures() -> None:
    spec = PROJECT_ROOT / "docs" / "SPEC.md"
    if not spec.exists():
        return
    src = spec.read_text(encoding="utf-8", errors="replace")
    block = re.search(r"## 5\..*?```python(.*?)```", src, re.DOTALL)
    if not block:
        return
    declared = set(re.findall(r"def\s+(\w+)\s*\(", block.group(1)))
    if not declared:
        return

    implemented: set[str] = set()
    for p in PROJECT_ROOT.rglob("src/**/*.py"):
        try:
            tree = ast.parse(p.read_text(encoding="utf-8", errors="replace"))
        except SyntaxError:
            continue
        for node in ast.walk(tree):
            if isinstance(node, ast.FunctionDef):
                implemented.add(node.name)

    missing = sorted(declared - implemented)
    if missing:
        warn(f"[签名] SPEC §5 声明但未实现：{missing}。"
             f"（可能是未到阶段，也可能漏实现了——需要人工确认，不是自动判错）")


# ── 检查 7：抓取产物的「源里有没有我要的内容」─────────────
def check_source_usefulness() -> None:
    """对应 wb 建议 3 的修正版：用目标文号做布尔判断，不用关键词命中率。
    关键词命中率会产生大量假阳性（实测房管局 39% 命中，但一条都不对口）。"""
    lst = PROJECT_ROOT / "data" / "processed" / "list.jsonl"
    if not lst.exists():
        return
    records = []
    for ln in lst.read_text(encoding="utf-8").splitlines():
        ln = ln.strip()
        if ln:
            try:
                records.append(json.loads(ln))
            except json.JSONDecodeError:
                continue
    if not records:
        return

    # 新鲜度
    years = [y for y in (re.search(r"/t(20\d{2})", r.get("path", "")) for r in records) if y]
    if years:
        newest = max(int(y.group(1)) for y in years)
        if newest < 2025:
            fail(f"[新鲜度] list.jsonl 最新内容 {newest} 年，距今超过 1 年，疑似死数据。")

    # 目标文号（硬指标）
    all_text = json.dumps(records, ensure_ascii=False)
    for dn in TARGET_DOC_NUMBERS:
        if dn not in all_text:
            warn(f"[硬指标] list.jsonl 中未找到 `{dn}`。"
                 f"注意：不命中不一定等于源不对，也可能是翻页不够——"
                 f"2026-09-26 实测该文号在 bgtwj 第 10 页。**先确认翻页范围，再下结论。**")


def main() -> int:
    checks = [
        ("单文件行数", check_file_length),
        ("静默吞错", check_silent_except),
        ("显式编码", check_encoding),
        ("JSONL 完整性", check_jsonl),
        ("expected_samples 真对比", check_expected_samples),
        ("SPEC 签名同步", check_spec_signatures),
        ("数据源有效性", check_source_usefulness),
    ]

    print("=" * 72)
    print("交付前自检")
    print("=" * 72)
    for name, fn in checks:
        try:
            fn()
        except Exception as e:
            fail(f"[{name}] 检查本身崩了：{type(e).__name__}: {e}")
        print(f"  ✅ {name}")

    print()
    if warnings:
        print(f"警告 {len(warnings)} 条（不阻断，但必须逐条看过）：")
        for w in warnings:
            print(f"  ⚠️  {w}")
        print()

    if problems:
        print(f"❌ 未通过，{len(problems)} 个问题：")
        for p in problems:
            print(f"  ❌ {p}")
        print()
        print("修完重跑。这些不处理，等于把问题推到后面才发现。")
        return 1

    print("✅ 自动检查全部通过。")
    print()
    print("⚠️  但脚本只能查可枚举的问题。交付前还必须回答三个问题：")
    print("   1. 这批数据真的达到目的了吗？（去数，不要凭感觉）")
    print("   2. 若有检查失败，失败的真实原因是什么？（别被布尔判断骗了）")
    print("   3. 有没有脚本没报警但你觉得不对劲的地方？")
    return 0


if __name__ == "__main__":
    sys.exit(main())
```

## 四、为什么这么设计

| 设计点 | 理由 |
|---|---|
| **脚本 + SKILL.md 两个文件，不是一个** | 只有文档的 skill 会退化成「又一份 CLAUDE.md」，CC 照样忘。**必须有退出码才有牙齿** |
| 用 dynamic context injection（`!` 语法） | AI 看见的是**真实执行结果**，不是它自己推测的。这是 CC 相对标准独有的能力 |
| 硬指标失败时报 `warn` 不报 `fail` | 2026-09-26 的教训：`0 命中` 可能是翻页不够，**自动判错会误导**。所以脚本提醒 + 人工查原因 |
| 每个检查项打印「为什么重要」 | 否则 CC 会把报警当噪音忽略掉 |
| 最后强制输出三个问题 | 把「不可枚举的 40%」显式摆出来，避免脚本全绿就以为万事大吉 |
| 每次踩新坑就往脚本里加检查 | **文档会忘，脚本不会** |

## 五、还能更硬一层（我没验证过，仅供参考）

Claude Code 有 hooks 机制（PreToolUse / Stop 等）。理论上可以在「AI 准备结束回合」时自动触发检查，做到**真正的强制**，连 AI 自己都绕不过去。

**我不确定具体配置方式**——没有查证过 hooks 的确切语法，不想写成错误的规格。若你想做，建议让 CC 自己查 Claude Code 官方文档的 hooks 章节确认后再定。

## 六、给 wb 的同一份

因为遵循 Agent Skills 开放标准，**这份 SKILL.md 我这边也能加载**。
如果你想让我以后每次介入审查时都按这套清单走，可以把 `SKILL.md` 也放一份到我的 skills 目录（`~/.workbuddy/skills/deliver-check/SKILL.md`）。

**好处**：wb 和 CC 用同一份清单，不会出现「两边的标准不一样」。
**代价**：两边都要维护同一份——建议约定「以项目里 `.claude/skills/` 那份为准」。

## 七、我不确定的点

1. Claude Code 的 `/skill-name` 在中文环境下是否支持中文技能名 —— **未验证**，建议用英文目录名 `deliver-check`
2. hooks 方案是否可行 —— **未查证**（见第五节）
3. 这套检查跑一次要多久 —— 取决于项目规模，我没在本项目实跑过（脚本是现写的）
4. Claude Code 版本要求 —— 我查到的是当前文档版本，**我没确认你的 CC 是哪个版本**。太老的版本可能不支持 skills，建议 CC 先确认版本。
