## 四、步骤

1. **站点活性**：对每个站点，记录本次抓到的页面是否可访问、页面内容是否为该站点真实内容。**不要**用单篇政策的发布年份判断"死数据"——很多政策本身就是 2020 到 2024 年发布的，仍然有效或需要标注状态。单篇的时效交给 `policy_status` 字段，本任务统一写"未核实"，由 Claude Code 后续核实。
2. **软 404 判据**：区级站点的软 404 行为与市级不同（见 `_handoff/CONTEXT.md` 第 153 条：汉阳区失效页直接返回真 404）。**不要套用市级的 title 判据。** 对每个 URL 记录 HTTP 状态码和正文长度，异常的报错。
3. **正文容器实测**：对每个站点，先确认正文所在的 HTML 容器（打印 class/id），再写抽取逻辑。**不得凭猜测选择器。** 每个站点的容器名记入报告。
4. **断言**：
   - 单个 URL 抓取失败 → 报错并记录，**不得静默跳过**
   - 候选记录数低于 12 减去允许失败数（允许失败数写在脚本顶部常量里，并在报告中说明取值理由）→ 整体报错
   - 正文长度 < 500 字符 → 报错
5. **抽样**：抓完随机抽 2 条，打印标题、发布日期、正文前 200 字，贴进报告。
6. **自检**：跑第六节的验收命令。

**发布日期**：优先取页面元数据；取不到则从高频日期推断并声明来源；都没有则留空，**不得编造**。
