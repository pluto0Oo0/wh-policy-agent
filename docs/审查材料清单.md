# 给审查者的材料清单

> **用途**：每次请外部审查者（wb）审查时，按本清单提供材料。
> **原则**：**给原始材料，不给转述。** 汇报文档只是索引，不是审查依据。

---

## 一、发什么

### 必发（核心材料 —— 审查的主力依据）

| 文件 | 为什么必发 |
|---|---|
| `docs/SPEC.md` | 项目的完整需求和技术设计，所有判断都在这里 |
| `notes/decisions.md` | **10 条技术决策**，每条含"为什么这么选、代价是什么"。**这是审查的重点** |
| `docs/抓取自检清单.md` | 防错机制。审查者应重点看"还漏了什么情况" |
| `docs/PLAN.md` | 18-22 周计划，看工期安排是否现实 |
| `进度汇报.md` | **索引**——先读这个了解背景，再去看上面几份 |

### 建议发（能验证"说的和做的是否一致"）

| 文件 | 为什么 |
|---|---|
| `src/ingest/crawl.py` | 抓取程序（270 行）。审查者可验证代码是否真的做了声称的那些检查 |
| `src/ingest/storage.py` | 存盘逻辑（68 行） |
| `scripts/build_data.py` | 执行入口（138 行） |
| `scripts/verify_data.py` | 数据验证程序（127 行） |
| `data/processed/list.jsonl` | **90 条真实数据**。可以直接看内容对不对 |
| `docs/research/02-*.md` | 调研报告，判断的事实依据 |

### 不要发（无意义的大文件）

| 路径 | 原因 |
|---|---|
| `.venv/` | Python 运行环境，几十 MB 的库文件，与项目逻辑无关 |
| `data/raw/*.html` | 抓下来的网页原件，6 个各 117KB。审查者不需要看网页源码 |
| `__pycache__/` | Python 自动生成的缓存 |
| `scripts/peek_*.py` `probe_*.py` 等 | 一次性的探测脚本，不是正式代码 |

## 二、要求审查者这样输出

**必须区分两类结论：**

| 类别 | 含义 | 可信度 |
|---|---|---|
| **【看过原始材料】** | 读了 SPEC / decisions / 代码后得出的 | 高 |
| **【仅凭汇报推测】** | 只看了 `进度汇报.md` 就下的判断 | **低，需另行核实** |

**为什么必须区分**：汇报是转述，转述会丢信息——数值会走样、判断依据会被压缩、代码逻辑看不见。
**"只看汇报就下的判断"是最不可靠的一类**，必须单独标出来。

**还要求标注：**
- **【不确定】** —— 它自己也拿不准的地方。**这部分最有价值**，因为不确定处往往藏着真问题

## 四、收到审查意见后怎么做

1. **意见先给项目所有者，不直接执行**（避免和主流程产生冲突指令）
2. **有分歧的地方，逐条核实再定**——分歧处往往藏着真问题
3. **每条意见必须能说清"改什么、为什么"**，不能只说"我觉得不好"
4. **采纳的写进 `notes/decisions.md`**，注明来源（如 "D11 · 采纳 wb 审查意见"）
