## 0. 先看结论（TL;DR）

1. 武汉光谷确实有 AI 应用类实习岗，但**明确招"本科 + 无实习经历"的高质量岗位极少**，大部分本科生能投的岗位集中在两类：小公司/初创（技术含量参差）与大厂的"非核心/标注类"岗位。
2. **Agent / 智能体是 JD 里出现频率最高的词（约 6 成），RAG 已进入"写了不加分、写浅了扣分"阶段**，提示词工程是硬性门槛，微调只有算法向岗位要，向量数据库多在面经里被追问而非 JD 里写。
3. **项目深挖占面试提问的 60%–80%**，纯八股在中小厂波动极大（0–50%）。面试官识别"教程项目"的方式是**追问失败模式和数据细节**，不是问你用了什么框架。
4. **没有找到**"民办本科投武汉 AI 应用实习通过率"的公开数据。能找到的最接近的量化数据是：51job《2026 届校招 AI 人才需求报告》中"名校学历"重要性仅排第 5（28.8%）；智联《2026 人力趋势报告》中 52.9% 企业把"项目成果或样本"列为最可信凭证，超过学历（41.0%）。
5. 寒假实习（1–2 个月）在武汉这类岗位里**几乎不成立**：样本中约 1/4 的岗位要求 6 个月以上，3 个月是主流下限。

**读法**：
- Agent 是 2026 年武汉 JD 的绝对主线，但**多数只停留在"参与 Agent 能力构建"**，不要求你从零造框架。

- **向量数据库很少在 JD 写，却高频出现在面经追问里**（凌脉面经问 Qdrant 与 Redis 分工、BigKey 风险）。这是"JD 不考、面试考"的典型项。
- **微调是算法岗的事**，AI 应用开发岗几乎不要。
- **AI 编程工具（Cursor/Claude Code）是 2026 年新增的隐形门槛**，4 条 JD 直接写进任职要求。

## 五、总结：一个软件工程大三学生，做什么项目最有区分度？

**结论先行：做"有真实用户 + 有可量化结果 + 有失败模式可讲"的 Agent 类工程项目，而不是再做一个 RAG 知识库问答。**

### 推荐的三个方向（按区分度从高到低）

**方向 A：能讲清楚"工具调用 + 权限边界 + 失败重试"的 Agent 系统（最高区分度）**
- 理由（有数据支撑）：
  - Agent 是武汉 JD 里出现频率最高的词（16/25 ≈ 64%）。
  - 但**面经里被追问最狠的恰恰是工程细节**：工具如何注册、参数如何校验、如何限制工作区、危险操作是否人工审批、如何阻止重复调用（凌脉面经原文 5 连问）。**大多数只有教程经验的候选人答不上来**——这就是区分度所在。
  - 面试官明确说"过度强调 LangChain 会显得缺少基础知识"，说明**手写/自研轻量框架 > 套框架**。安软和小红书面经都问了"为什么自研不用开源框架"。
- 反例（不要做）：用 Coze/Dify 拖一个工作流就说自己"做了 Agent"。JD 里 Dify/Coze 是"优先"加分项，不是核心；筛选者明确把"没用过几个模型、自己做的 agent 自己也不用"列为减分项。

**方向 B：嵌在真实业务里、有量化前后对比的小工具（次高区分度）**
- 理由：
  - 智联数据：52.9% 企业把"项目成果或样本"列为最可信凭证，**超过学历**。
  - 有真实落地的正例：双非本科生做内部合同审查助手，"把单份初审从 40 分钟压到 8 分钟"→ 拿到大厂 offer；小厂实习生把工具调用准确率从 65% 提到 95% → 通过字节终面。
  - 非科班开奶茶店做点餐系统的案例说明：**场景真实 > 技术华丽**。
- 反例（不要做）：仿 XXX（仿美团、仿商城）类项目。牛客面试官手记把它们直接归为"培训机构模板"。

**方向 C：用 AI 编程工具（Cursor / Claude Code）交付并公开全过程（低成本加分项）**
- 理由：4 条武汉 JD 把 AI 编程工具写进任职要求（拓尔思、长飞、华讯、趣链）。面经里高频问"项目中哪些代码由 AI 生成、哪些自己手写"（安软）、"如何用 AI 工具辅助开发"（界外科技、淘天）。
- 关键动作：**GitHub 仓库 + README + 提交记录**。筛选者明确说"写了很多项目不给 github 链接，会让我觉得都是假的"。

### 已经不稀缺的方向（明确列出，避免浪费时间）

| 方向 | 不稀缺的证据 |
|---|---|
| **单轮 RAG 知识库问答（LangChain + 向量库 + Prompt 三件套）** | 掘金（2026-07-18）："当十个候选人里有九个都在写同一个项目时，这个项目就不是加分项了，变成了**减分项**"；牛客帖："清一色的简历，2 个 Agent/RAG 的项目" |
| **"了解 LLM 原理""用过 LangChain"这类技能罗列** | 双非硕心得帖："很多候选人都能说出'了解 LLM 原理''用过 LangChain'，但真正能被记住的是有明确工程能力标签的人" |
| **微调 / 从零训模型**（对应用岗） | 武汉 JD 中只有 3/25 提到微调，且都在算法岗（VLA、工业算法）。应用开发岗不要。对无 GPU 的本科生，性价比极低 |
| **堆砌技术栈的大而全项目**（微服务 + 分库分表 + 多级缓存 + MQ 塞进一个 demo） | 牛客面试官手记："纯属'大炮打蚊子'…暴露无遗" |
| **证书 / 课程结业** | 网易转载调研："企业对其真实能力的信任度较低，赋予较低的需求权重" |

### 三个可以直接执行的落点

1. **必带 GitHub 链接**，README 写清楚：解决什么问题、你自己写的部分、失败案例、量化前后对比。筛选者说不给链接直接判假。
2. **准备"我的系统什么时候会错"这个故事**。安软面经连续 6 题围绕 RAG 评测的可信度追问——这是 2026 年最典型的识破点。
3. **先解决"实习时长"这个硬约束**：武汉样本里 ≥6 个月占约 1/3，3 个月是主流下限；寒假 1–2 个月**没有对应岗位**。现实做法是寒假入职 + 春季学期兼职做满 3 个月。
