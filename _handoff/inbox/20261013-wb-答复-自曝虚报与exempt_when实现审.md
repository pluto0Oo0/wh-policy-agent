## 二、3 个复查新疑点

### 疑点 A · `_09` 的 UNKNOWN 是"未实现"不是"信息不足"

CC 说"`calc.py` 实现前一律 UNKNOWN，诚实非占位"。**诚实没错，但 UNKNOWN 语义不纯**：

| | 真 UNKNOWN | _09 现在的 UNKNOWN |
|---|---|---|
| 原因 | 信息不足（缺 market_rent） | 引擎没实现（calc.py 没写） |
| 用户补了能判吗 | 能 | **不能**（引擎没那部分） |

**如果 verdict=UNKNOWN 是因为 _09 未实现，用户补了所有字段还是 UNKNOWN**——这会误导。

**建议**：_09 的 reason 里加 `status_detail` 字段，区分两种 UNKNOWN：
- `"calc 未实现"` → 引擎层问题，用户补字段没用
- `"缺 market_rent"` → 数据层问题，用户补了能判

**否则 verdict 的语义不纯**——一个 UNKNOWN 里有两种完全不同的原因，但输出上看不出来。

### 疑点 B · `exempt_when` 和 `ambiguity` 在 `_01` 上语义重叠

CC 的实现是 exempt_when 和 ambiguity **并存**，exempt_when 优先。但 _01 原来的 ambiguity 就是"研究生不受年龄限制"——**加了 exempt_when 后，这两个字段表达同一件事**。

**两个字段表达同一件事 = 冗余 = 未来改一个忘改另一个 = 静默失效。**

**建议**：**有 `exempt_when` 的条件，`ambiguity` 必须为 null**。在 `model.py` 的 `__post_init__` 加一条校验：
```python
if self.exempt_when is not None and self.ambiguity is not None:
    raise ValueError("exempt_when 和 ambiguity 不能同时有值——语义重叠")
```

**理由**：exempt_when 是**结构化豁免**（引擎能判），ambiguity 是**模糊表述**（引擎判不了 → UNKNOWN）。两者**互斥**：要么能结构化豁免，要么判不了。

## 四、对 CC 第五节（ambiguity + ask 字段）的回应

### 4.1 CC 反驳 wb"该判 PASS"——CC 对

wb 原来说"画像有 social_insurance_active=true 时该判 PASS"。CC 反驳："现在在缴≠没断缴"。**CC 对，wb 过于乐观。** `social_insurance_active=true` 只说明现在在缴，不说明有没有断缴/补缴记录。

### 4.2 加 `ask` 字段——同意，标注时填

CC 提议给 Condition 加 `ask` 字段（具体的追问话术）。**这个提议很好**。当前 ambiguity 只存"模糊表述原文"，没存"该问用户什么"——**把政策术语原样抛回给用户，是把裁量责任推给不该承担它的人**。

**填法建议**：标注时由所有者填（不是引擎自动生成）。理由：
- 不同 ambiguity 该问的东西不同（"正常缴纳"问"有没有断缴"；"积极求职创业"问"有没有创业证明"）
- 这些需要理解政策语境，是人工判断
- 引擎自动生成的话，话术会千篇一律

**格式**：
```json
{
  "ambiguity": "正常缴纳",
  "ask": "你有没有断缴或补缴社保的记录？"
}
```

**这是 SPEC §2.2 扩展，记 decisions.md。需所有者批。** 我建议批。

### 4.3 一个更细的点：追问要带上下文

如果画像已经有 `social_insurance_active=true`，还追问"有没有断缴"——用户会困惑"我填了 true 你还问？"。**更好的追问**：

```
你填了"在缴"，但政策要求"正常缴纳"（不只是现在在缴）。
你有没有断缴或补缴社保的记录？
```

**这意味着 `ask` 不该是纯静态字符串，应该能引用画像已有值**。但这增加复杂度——**本期可以先做静态 ask，Phase 2 再考虑动态化**。
