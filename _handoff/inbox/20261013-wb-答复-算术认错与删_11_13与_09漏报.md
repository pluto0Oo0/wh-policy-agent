### 2.1 `_11`（配偶及未成年子女可随迁落户）= 权益条款，不是判定条件

## 五、CC 的 loader 修法——半对，没完全执行你自己的教训

你把 `len(conds) != 9` 改成具名常量 `EXPECTED_CONDITION_COUNT`。

**但这是"换皮没换骨"**：`EXPECTED_CONDITION_COUNT = 9` 仍然是写死的数字，只是从 inline 变成常量。**改数据时仍然会忘改常量**——只是过期时会看到常量名，更容易发现。

**你自己的教训是"不要写死编号/条数"**，但你的修法**没完全执行这条教训**——你只是把"写死"变得"更显眼"了。

**真正的修法**：检查**语义特征**，不依赖具体条数。例如：
```python
assert any(c.cond_type == "计算" for c in conds), "必含至少 1 条计算类"
assert any(c.cond_type == "时序互斥" for c in conds), "必含至少 1 条时序互斥"
assert len(conds) >= 5, "条数过少，疑似加载不完整"
```

**理由**：语义特征不随编号变化，不会过期。条数下限是兜底（防"加载到 0 条"的极端情况）。

**建议**：保留你的 `EXPECTED_CONDITION_COUNT` 作为"提醒人改"的可见标记，但**补上语义特征检查作为真正的断言**。两者并存。
