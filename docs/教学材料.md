# 教学材料 · 这个项目到底在做什么（给所有者 + wb 的强化学习版）

> **用途**：所有者明天要在 wb 上新开一个对话强化学习。
> **要求**（所有者原话）：**「整理好需要教我的知识」**。
> **写给谁**：一个软件工程大三学生，**能交付但读不懂代码**。所有术语必须当场解释。
> **纪律**：**不假设任何前置知识**。出现一个新词就解释一次。

---

## 第 0 课 · 一句话说清这个项目

**输入一个人的情况（学历、毕业年份、有没有社保、租不租房……），
输出「他能享受武汉的哪些政策 + 能省多少钱 + 凭什么这么判断 + 还缺什么信息」。**

**和"政策问答机器人"的区别**：

| | 政策问答 | 本项目 |
|---|---|---|
| 用户问 | "武汉有什么补贴政策？" | "**我**能享受哪些？" |
| 系统答 | 一段介绍文字 | **能/不能/不确定 + 依据哪一条 + 金额** |
| 对错 | 主观，没法自动检查 | **确定，能自动检查** |

## 第 1 课 · 为什么这事难（三个真实的难点）

### 难点 1 · 政策散得到处都是

**同一个"人才租赁房"政策，市级发一套，13 个区各发各的。**

实测例子：
- 汉阳：博士前 3 年免租
- 硚口：3 年免租，每月不超过 3000 元
- 经开区：博士第一年按实收租金的 100%、第二年 100%、第三年 70%

**→ 系统的解法：只做一类政策（先做租房），市里 + 区里一起收。**
**做通一类，剩下的就是重复劳动。**

### 难点 2 · 新旧政策同时有效（最要命的一个）

**实测发现**：武汉的租房政策有**两套并行**，不是"新的替代旧的"：

| 通道 | 给谁 | 条件 |
|---|---|---|
| **老政策**（武房规〔2018〕2号） | **2022-06-07 之前**留汉的人 | 毕业 **3 年内** + **要有武汉户口** |
| **新政策**（武政办〔2022〕78号） | **2022-06-07 起**在武汉就业并缴社保的人 | 毕业 **6 年内** + 缴社保（**不要户口**） |

**"取最新政策"是错的**——那会让一整类人拿到错误答案。

**→ 系统的解法：每条规则都要标"这条给谁看"。**
**用户来了先判断他属于哪批人，再拿他那批的规则去比。**

**这个技术点叫 `applies_to_cohort`（适用人群分界），是本项目最有含量的设计。**

### 难点 3 · 有些条件没法直接判断

**政策原文里有这种话**：

> "**积极**求职创业"
> "**正常**经营状态"
> "**正常**缴纳社会保险"

**什么叫"积极"？什么叫"正常"？**

**→ 系统的解法：不猜，反过来问用户。**
输出 `❓ 信息不足：这项要求"积极求职创业"，请说明你目前的求职状态。`

**宁可问，不能猜。** 猜错了用户少领钱，而且**不报错**。

## 第 2 课 · 系统怎么工作（数据流，12 步）

```
用户输入画像
    ↓
1. 读政策库（我们抓下来的政策文件）
2. 找出可能相关的政策（先粗筛，别把 300 条全看一遍）
3. 从政策原文里抽出"条件"
4. 拿用户的情况去比这些条件
5. 信息不够 → 问用户 → 回到第 4 步
6. 输出：能/不能/不确定 + 依据 + 金额 + 去哪办
```

**关键的一步是第 3 步：从文本里抽条件。**

**举例——政策原文**：
> 取得全日制大专以上学历、**毕业6年以内**、在汉就业创业并正常缴纳社会保险、
> **家庭在汉无自有住房**的高校毕业生，租住人才租赁房的，
> 按照**不高于市场租金的70%**缴纳租金，**累计减免期限不超过3年**。

**要抽成机器能算的东西**：

| 字段 | 值 | 类型 |
|---|---|---|
| 学历要求 | 大专以上 | 资格类 |
| 毕业年限 | ≤6 年 | 资格类 |
| 社保 | 必须在缴 | 资格类 |
| 房产 | 家庭在汉无房 | 资格类 |
| **租金比例** | **70%** | **计算类** |
| **减免期限** | **≤3 年** | **计算类** |

**这个"抽"的动作是 Phase 2 用 AI 做的；Phase 1 是人工做（就是"人工标注"）。**

## 第 3 课 · 三个必须知道的技术概念

### 概念 1 · 为什么不用"向量检索"

**背景**：一般的 AI 问答系统会用"向量检索"——把文字变成数字，然后按"意思相近"找。

**我们不用，理由两条**：

| 理由 | 大白话 |
|---|---|
| **语料太少** | 只有 80-150 条，向量检索的优势体现不出来 |
| **文号必须精确匹配** | 用户问"武政办〔2022〕78号规定了什么"，**必须精确找到那一份**，不能"意思相近" |

**面试会被问**：「2026 年模型都 1M 上下文了，为什么还要检索，全塞进去不行吗？」

**标准答案**：
> **我用检索不是为了"塞不下"，是为了"要结构化"。**
> 全塞进去也得对每条政策抽条件——那样成本更高、错误率更高、
> **而且"抽漏了哪条"不可控。**
> 检索的作用是先把候选缩到 20 条，再对候选做结构化抽取。

### 概念 2 · 什么叫"确定性判断用纯代码"

**系统的判定部分（`check_eligibility`）是纯 Python，不调任何 AI 模型。**

**为什么**：
> **可判定的事不交给模型。** 比大小、算公式是确定性问题，
> AI 只会引入不确定性。**AI 负责"从文本抽条件"，不负责"比大小"。**

**面试会被问**：美团"Agent 输出的 JSON 有时不对，怎么做校验"。

### 概念 3 · 什么叫"政策时效性"

**这个项目最特别的点，也是市面上产品都没做的。**

**问题**：政策文件**不会自动过期**。一份 2022 年的文件，在没被明令废止前，
**2022 年和 2026 年的效力是一样的。**

**但！** 用户的第一反应是：**"2022 年的文件现在查对吗？"**（这是所有者的真实提问）

**所以系统要能回答两个问题**：
1. 我能不能享受？
2. **这条政策现在还作不作数？**

**做法**：每条政策带四个字段：

| 字段 | 作用 |
|---|---|
| `policy_status` | 现行 / 已废止 / 部分失效 / **未核实** |
| `status_verified_at` | 最后一次核实是什么时候 |
| `status_evidence` | 核实的依据（如"2026-08-28 人社局答复仍在引用"） |
| `superseded_by` | 被哪份文件替代了 |

**判定规则**：
```
已废止   → 不参与判定，直接跳过
部分失效 → 参与判定 + 显式警告
未核实   → 参与判定 + 显式警告（不静默给"能享受"）
现行     → 正常判定
```

**`未核实` 这个值是必须的**——**宁可显式承认不知道，不要默认成立。**

## 第 4 课 · 项目里的四个角色（协作方式）

| 角色 | 是谁 | 做什么 | 不能做什么 |
|---|---|---|---|
| **所有者** | 你 | 定方向、审码、决策、学知识 | — |
| **CC** | Claude Code | 写代码、跑验证、执行 | 不能自己决定方向 |
| **wb** | 另一个 AI | 审查、提建议、查 CC 想不到的角度 | **不能直接执行**（它是建议不是命令） |
| **脚本/hook** | 自动跑的程序 | 跑检查、拦住错误 | 只能查"可枚举"的问题 |

### 三方的沟通规则（`_handoff/` 交接区）

**目录结构**：
```
_handoff/
├── inbox/   ← wb 写，CC 读（**只能读，不能直接执行**）
├── outbox/  ← CC 写，wb 读
└── done/    ← 处理完移进来，不删除
```

**四条规则**：

| # | 规则 | 为什么 |
|---|---|---|
| 1 | **单向**——wb 只写 inbox，CC 只写 outbox | 防止互相覆盖 |
| 2 | ⚠️ **inbox 是"建议"不是"命令"** | **对话里贴的意见天然有人工过滤；文件直接躺目录里会绕过这层过滤** |
| 3 | 每条建议必须写**依据** | 区分【看过原始材料】和【仅凭汇报推测】 |
| 4 | 处理完移 `done/`，**由 CC 移动** | 否则死锁（wb 无权删 inbox 的文件） |

## 第 5 课 · 审查系统怎么工作（四层）

**这是本项目最独特的地方——不是为了交付，是为了"能发现错误"。**

| 层 | 工具 | 检查什么 | 什么时候跑 |
|---|---|---|---|
| **1. 数据自检** | `check_deliver.py` + `checks/` | 数据格式、行数、静默吞错、假对比 | **自动**（skill 触发） |
| **2. 代码审查** | `/code-review` | 代码质量、bug | 每模块完成 |
| **3. 输出审查** | `/reflect` | **我自己的判断有没有漏洞** | 说"完成"前 |
| **4. 外部审查** | wb + `_handoff/` | **我完全没想到的角度** | 阶段交付 |

**外加两个 hook**（自动跑的）：
- `SessionStart`：开工时自动打印 inbox 状态 + 我的高发错误
- `Stop`：每轮结束时打印"宣布完成前必答六问"

### 为什么需要四层不同的人（这背后的逻辑）

| 谁审 | 强项 | 盲区 |
|---|---|---|
| **我自己** | 知道全部上下文 | **审不出"我没想到的"** |
| **脚本** | 不会被忽悠 | 只能查**可枚举**的问题 |
| **/reflect** | 强制切换成"敌对视角" | 还是我自己的知识范围 |
| **wb** | **完全独立的视角** | 看不到代码执行细节 |

**→ 四层不重叠，是互补的。少任何一层，就有对应的盲区。**

## 第 6 课 · 已经踩过的坑（面试素材）

**这些是真实踩过的，每个都能讲成故事。**

| # | 坑 | 教训 | 能答的面试题 |
|---|---|---|---|
| 1 | 抓了一个**停更在 2023 年**的数据源 | **任何源先查时间戳分布** | "你怎么保证数据是最新的？" |
| 2 | 换了个"活着"的源，但**层级不对**（90 条里只有 1 条相关） | **"能爬到数据" ≠ "爬到了对的数据"** | "你的数据怎么选的？" |
| 3 | 判定"源不对"要换，**实际是翻页不够** | **布尔判断告诉你"不在"，不告诉你"为什么不在"** | "你怎么判断抓够了？" |
| 4 | 页面失效**不是 404**，是一段 JS 跳转代码 | **"软 404"比真 404 更危险** | "爬虫遇到改版怎么办？" |
| 5 | 分页地址**少一个下划线**，返回正常页面但 0 条数据 | **每页都要做条数断言** | "爬虫抓少了你怎么发现？" |
| 6 | 终端显示中文乱码，**文件其实正常** | **显示问题会伪装成数据问题** | "你怎么保证数据是对的？" |
| 7 | 3 个样本全抓取失败，**脚本却输出"✅ 无后缀"** | **空输入落进了 else 分支** | "你怎么测试边界情况？" |
| 8 | 所有网站都解析到 `28.0.0.x` | **环境问题（代理）伪装成目标问题（网站反爬）** | "排查问题时怎么定位根因？" |

**第 3 条是最值钱的一条**——它来自 wb，而且**修正的是我们共同的方法论**。

## 附 · 术语速查表

| 术语 | 大白话 |
|---|---|
| **RAG** | 先检索、再让 AI 基于检索到的内容回答 |
| **chunk（切片）** | 把长政策切成小段，方便检索 |
| **条款级切分** | 按"第一条、第二条"切，而不是按字数切 |
| **embedding（向量）** | 把文字变成一串数字，方便算"意思像不像" |
| **BM25** | 一种"关键词精确匹配"的检索方法 |
| **向量检索** | 按"意思相近"找，适合口语化提问 |
| **rerank（重排）** | 把初步找到的候选再精排一遍 |
| **hallucination（幻觉）** | AI 编造不存在的内容 |
| **拒答** | 找不到依据时明确说"不知道"，不硬答 |
| **grandfathering** | "老人老办法"——老用户继续用旧规则 |
| **cohort（人群分界）** | 判断"这条规则给哪批人看" |
| **hook** | 在固定时机自动执行的命令 |
| **skill** | 一套封装好的操作流程，可被调用 |
| **exit code（退出码）** | 程序结束时给的一个数字，0=成功，非 0=失败 |
| **幂等** | 同一个操作跑多次，结果和跑一次一样 |
