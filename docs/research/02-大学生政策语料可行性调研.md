# 报告-武汉大学生政策作为 RAG/Agent 项目语料的可行性调研

调研日期：2026-09-23（v2，含 4 路子 agent 并行补查结果）
调研对象：「武汉大学生政策」能否支撑一个 3-5 个月的 RAG/Agent 项目
证据标注：**[一手]** = 政府官网原文 / 官方文件原件 / 官方答复原件 / 原帖正文 / 实测 HTTP 响应；**[二手]** = 自媒体、技术博客、论文、培训平台、转述

> **v2 相对 v1 的三处推翻**（v1 由我单人调研，v2 由 4 个子 agent 补查后修正）：
> 1. 政策页「七段式模板统一」——**不成立**。33 个区级页面至少分 6-7 个模板族，七段式覆盖率不到一半。
> 2. 武汉人才工作网详情页「可直接读到正文」——**不成立**。它是 Vue SPA 空壳，必须走 `/gateway/` 接口；且前端硬编码列表只有 14 条，**漏掉了落户和住房这两条核心政策**（实际 16 条）。
> 3. "毕业三年内"是「僵尸页残留」——**不完整**。根子在市级武房规〔2018〕2 号，是**合法的"老人老办法"双轨**，不能简单取最新。

---

## 0. 结论先行

**数据基础成立，但"RAG"这个框架不成立；而且"政策"这个题材本身在面试市场不加分。**

1. **语料真实、可爬、条件写在正文里**——核心假设成立。
2. **但总量只有 80-150 条，且结构不统一、缺失效信号。**150 条不需要向量检索；真正的难点是条件结构化、人群分层、金额计算。
3. **最大的坑不是"检索不准"，是"你以为冲突是 bug，其实它是这个领域的正常形态"**——而且其中一类冲突是**合法的 grandfathering（老人老办法）**，系统必须做人群分层，不能简单取最新。
4. **赛道几乎空（GitHub `补贴 资格 大模型` 搜索结果为 0），但也因此没有"政策类=加分"的既有认知。**三篇牛客选题帖推荐清单里政策类零出现；RAG 本身已被评为"十份简历八份带"。**加分只来自三件别人都没做的事：判定闭环 + 自建评测集 + 冲突/拒答处理。**

**建议：项目定义为「政策条件判定 Agent + 人群分层 + 冲突可解释」，MVP 只做「安居/住房」垂直子类（约 30-40 条），必须做 ≥50 条来自真实提问的评测集。**

### 1.2 "毕业三年内"不是错误，是合法的"老人老办法"

**[一手]** 汉阳区政府 2024-07-11 明确定义：
> **武汉市老政策：**按照《武汉市大学毕业生保障性住房供给与管理办法的通知》（武房规〔2018〕2号），即**毕业3年内、拥有本市户籍**，家庭在全市无自有住房的高校毕业生，在资格期内享受市场租金的70%（合租）、80%（整租）租金优惠。
> 2022年6月7日之前留汉（以首次缴纳社保时点认定），未申请人才安居资格的高校毕业生，继续按照老政策执行。
URL: https://www.hanyang.gov.cn/zwgk_38/xxgkml/ggzypz/zfbz1/bzxzfzc/202407/t20240711_2427280.shtml

**[一手]** 武汉市住更局信访答复（2025-04-29）证明它至今对特定人群有效：
> 2022年6月7日之前留汉未申请人才租赁房的大学毕业生，按照武房规〔2018〕2号要求……即毕业3年内的大学毕业生，拥有本市户籍，家庭在本市无自有住房的，可申请大学毕业生租赁房。经核实，您在2020年已在武汉就业并且毕业时间超过3年，不符合上述规定的申请条件，江岸区相关部门据此拒绝了您的申请。
URL: https://zgj.wuhan.gov.cn/hdjl_44/lxgs_/202505/t20250507_2578076.shtml

**[一手]** 但市住更局 2022-04-18 的页面至今在线、无失效标注，导致用户误解（就是上面那位被拒的申请人）：
URL: https://zgj.wuhan.gov.cn/xxgk/zcfgyjd_1/zcwd/202204/t20220418_1957329.shtml

**→ 架构后果：每条条件必须带 `applies_to_cohort`（适用人群分界）字段，"取最新"是错的，要"取适用于该用户的那一套"。**这是本项目最有技术含量的一个点。

### 1.3 政策语料天然没有"失效信号"

**[一手]** 子 agent 逐区核查：**没有任何一区政府官网对已过时页面使用作废声明、失效标注或跳转提示。**
叠加发现：**至少 1/4 的政策页面根本没有可靠发布日期**（硚口 id 式页面、蔡甸/新洲情景页、武昌区企服中心页完全无日期；江汉区一篇"发文日期 2025-06-19"与 URL 的 `t20250710` 差 3 周）。

**→ 做"现行有效性判断"时，你既没有官方失效标记，又常常没有时间戳。这是本项目最难、也最值得做的功能。**

### 2.3 ⚠️ 武汉人才工作网：详情页也不是 SSR，且前端列表有遗漏

**[一手] 实测**（curl，带 UA，无 Cookie）：

```
GET https://dsj.whrcgz.gov.cn/bwdxs?id=062e1c69-0131-11ea-b44e-e82a444382df
HTTP=200 SIZE=12518
关键词命中：补贴:0 政策:0 申报:0 对象:0 条件:0 受理:0
与不带 id 的列表页字节数完全相同 → 详情页不是 SSR
```

**正确接口（免登录）[一手]：**

| 接口 | 用途 | 实测 |
|---|---|---|
| `GET /gateway/cmsserver/cms/article/{uuid}` | 政策正文（HTML 字符串） | ✅ `code:""`，返回 `contents` 字段含七段式 HTML |
| `GET /gateway/cmsserver/cms/article/getArticleList?categoryId=&currentPage=&pageSize=&keyword=` | 列表 | ✅ 返回 `total` |
| `GET /gateway/cmsserver/tag/selectAll` | 标签筛选 | ⚠️ `data:[]`，实际不可用 |

**实测条数 [一手]：** 大学生类 `categoryId=be427c3e-0130-11ea-a293-e82a444382df` → **total=16**；政策文件 → 8；江汉英才 → 2。

**关键坑 [一手]：** 前端路由 `bwdxsList` 的源码里 `data()` **写死了一个 14 项数组**，`created(){}` 为空（不调接口）。这 14 条里**没有**"普通高校大学生落户"和"大学毕业生租赁房"——而 `getArticleList` 查分类有 16 条，多出的正是这两条：
```
062df3ca-0131-11ea-a83e-e82a444382df | 普通高校大学生落户
062e1c68-0131-11ea-855d-e82a444382df | 大学毕业生租赁房
```
**→ 照着前端列表抓会漏掉落户和住房这两条核心政策。必须用 `categoryId` 查全。**

另：落户和安居在武汉这边是**外链到别的系统**（湖北公安政务服务平台 `wsgaj.chutianyun.gov.cn`、武汉人才安居网 `rcaj.whfgxx.org.cn:8081`），不在这个站内。

### 2.4 ⚠️ 湖北政务服务网：正确入口不是 `bszn_detail.html`

**[一手] 实测：** `bszn_detail.html?id=13151` 在整个站不存在（后端 `cty-wsbsdt-server-bszn` 明确回 404，不是我 URL 写错）。

**正确形式 [一手，从 `js/bmsy/bmsy.js` 提取 + 实测]：**
```
详情页 URL: /webview/bszn/bsznpage.html?transactCode=<32位十六进制>
详情接口:   POST /web/bszn/ykypt/standard/transact/project/getTransactInfoByTransactCode.jspc
            参数: transactCode=xxx&type=info     ← 少了 type=info 会报"未知错误"
列表接口:   POST /web/bszn/item_project_transaction
            参数: orgCode/taskType/regionCode/areaGrade/currentPage/pageSize/...
```

**看办事指南不需要登录**——上述接口在零 Cookie 下实测均返回 `code:1`。
**限制**：列表接口**没有关键词参数**（传 `keyword=毕业生落户` 被忽略，仍返回 total:1826365），只能按部门+区划浏览。**未能定位到"毕业生落户一件事"的 transactCode。**

**条件预检 [二手，随州市民政局操作手册]**：形态是**点选选项的引导问卷**（引导问卷选择 → 条件预检 → 表单填报），属**登录后的在线申报流程**，不是办事指南的一部分，也不是自由文本问答。

## 三、核心问题：条件写在正文还是办事指南？（Q2）

### 3.1 答案不变：写在政策正文里

**[一手]** 全市存在统一「七段式」模板，在市政府门户、武汉人才工作网、江岸区、江夏区、洪山区、武昌区、东西湖区、新洲区重复出现：

```
（一）政策内容 /（二）申报对象及条件 /（三）补贴标准
（四）文件依据 /（五）申请材料 /（六）业务流程 /（七）受理部门及联系方式
```

**→ 不需要追附件、不需要登录办事指南、不需要跨文档引用。附件（.docx）只是申请表模板。**

### 3.2 ⚠️ 但 v1 说的"模板统一"是过度乐观——实际至少 6 个模板族

子 agent 逐页核对 33 个区级页面后的结论：**部分一致，一个解析器吃不下。**

| 模板族 | 结构 | 出现处 |
|---|---|---|
| **A（主导，七段式）** | 政策内容/申报对象及条件/补贴标准/文件依据/申请材料/业务流程/受理部门 | 洪山、武昌、东西湖、新洲、市级专题 |
| **B（硚口九段式）** | 受理部门/政策类型/联系人/**申报时间**/**备注**/**支持标准**/申报条件/办理流程/政策依据 | 硚口招才引智页——**支持标准排在申报条件之前**，会被误抽 |
| **C（政务服务事项式）** | 申领对象/权利义务/申请条件/申请材料/办理流程/办理时限/办理地点/结果告知/咨询电话 | 汉阳区——**没有"补贴标准"字段**，金额要从别的页拼 |
| **D（东湖高新事项清单式）** | 事项名称/办理类型/**办事条件（内含不分层子段"补贴标准"）**/申报材料 | 东湖高新——补贴标准被降级为子段，且"特别提醒"里藏硬要求 |
| **E（江岸五段短指南）** | 申请对象及条件/申报材料/政策依据/办理流程/受理机构 | 江岸——**只有 5 段，且顺序完全不同** |
| **F（蔡甸/新洲 tab 式）** | 概述/相关政策标准/申报对象及条件/**受理部门**/申报材料/申报流程/常用查询/常见问题 | 蔡甸——**同一政策，与新洲用了两套字段顺序** |
| **G（非结构化）** | 问答式新闻解读 / 房源通告里夹 20 个楼盘价格表 | 经开区、江汉区——直接全文切片会把 2000+ 个租金数字喂进语料，**严重污染检索** |

**→ 建议：不要以"区"为单位建解析器，要以"模板族"为单位。且必须为每条 chunk 强制保留 `文号 + 发布日期 + 适用人群边界` 三项 metadata——本次发现的所有冲突都是靠"谁更晚/依据哪个文号"裁决的，而偏偏这三项在多个区页面上缺失或被弱化。**

## 四、爬取难度（Q3）

| 项 | 实测结果 |
|---|---|
| 登录墙 | 政策正文**全部免登录**，含湖北政务服务网办事指南接口（零 Cookie 实测 `code:1`） |
| 反爬 | **未触发**任何验证码、403、限流。6 轮并行抓取 + 子 agent 大量 curl 全部成功 |
| robots.txt | `wuhan.gov.cn/robots.txt` **不存在**（返回首页） |
| 正文格式 | 绝大多数静态 HTML；PDF 为**文字层可读**，非扫描件 |
| 两个 SPA 站 | 武汉人才工作网、湖北政务服务网需走接口（接口地址已实测确认，见 2.3/2.4） |
| 需登录才能拿的 | 只有实际申报系统（武汉人才安居网需注册+手机验证；湖北政务服务网"条件预检"在登录后申报流程内） |

**难度评级：低到中。**静态站用 `requests` + `BeautifulSoup` 即可；两个 SPA 站需要抓接口，但接口已定位且免登录。**不需要 Playwright、不需要打码、不需要代理池。**

**负面含义：门槛低 = 别人也能做。"我把数据爬下来了"不能当亮点。**

## 五、条件质量：占比与类型分布（Q4 / Q5）

### 5.1 样本说明

- 样本**非随机**（搜索可触达 + 页面可打开）
- v2 样本量：**33 条区级/市级政策页 + 5 条学校通知 + 1 条省级新规**，其中我读到完整条件原文的约 **30 条**
- v1 的 24 条含在 v2 内

### 5.2 结果

| 指标 | 数值 |
|---|---|
| 含"申报对象及条件"独立段落 | **约 90%**（模板 B/C/D/E/F 也有"申报条件"段，只是位置和字段名不同） |
| 条件**全部可判定** | **约 70%** |
| 含**至少一个模糊/需裁量**表述 | **约 30%** |

**模糊项原文（[一手]）：**"积极求职创业"（武人社函〔2025〕253 号）、"正常经营状态"（创业补贴）、"正常缴纳社会保险"（人才租赁房）、"零就业家庭…但不建议按此类申请"（某校通知，原文如此）。

**→ 30% 的模糊项不是缺陷，是 Agent 的用武之地：`check_eligibility` 遇到这些字段返回 `UNKNOWN` + 触发主动追问，而不是硬给答案。这是你能讲的设计决策。**

### 5.3 条件类型分布

| 类型 | 占比 | 可程序化 |
|---|---|---|
| **资格类**（学历/年龄/毕业年限/户籍/住房/身份枚举） | 约 45% | 是 |
| **计算类**（金额/比例/封顶/时长/人数/公式） | 约 25% | 是，最有价值 |
| **材料类**（交哪些证） | 约 20% | 是（本质是清单） |
| **时序/互斥类**（时限/只能一次/不重复享受） | 约 10% | 是，最容易漏 |

**v1 担心"大学生政策多为纯资格类、缺计算类"——实测不成立，计算类约 25% 且形态丰富。**

## 七、版本冲突全清单（Q7）—— 本项目最大的坑，也是最大的机会

### 7.1 冲突类型一：合法双轨（grandfathering）—— **不能取最新**

| 通道 | 适用人群 | 条件 |
|---|---|---|
| 老政策（武房规〔2018〕2 号） | 2022-06-07 **前**留汉、未申请人才安居资格 | 毕业**3年内** + **拥有武汉市户籍** + 家庭无自有住房；70%（合租）/80%（整租） |
| 新政策（武政办〔2022〕78 号） | 2022-06-07 **起**在汉就业创业并缴社保 | 毕业**6年内** + 社保 + 家庭无自有住房；70%，博士免2年、硕士免1年 |

### 11.2 ⚠️ 最强的一条反驳：检索变好 ≠ 端到端变好

> "domain-specific fine-tuning improves retrieval metrics but **does not consistently improve end-to-end question answering performance. In some cases, stronger retrieval counterintuitively leads to more confident hallucinations when relevant documents are absent from the corpus**."

**[一手]** 同一论文的三类核心错误：
> "**Cross-jurisdiction retrieval errors.** Because many AI policies deliberately share and reuse similar terminology, the retriever occasionally returns passages from the wrong jurisdiction… the generator may incorrectly attribute the retrieved content to the queried jurisdiction."
> "**Complex query interpretation.** …queries involving multiple documents or nuanced constraints… the retriever may prioritize semantically similar passages rather than those that satisfy all query conditions."

**→ "跨辖区术语混淆"直接对应武汉 13 个区互相抄政策的问题。这条论文是"为什么不能只做检索"的最硬证据。**

### 12.1 数据基础是否成立？

| 维度 | 结论 |

### 12.2 最大的坑是什么？

**不是"检索不准"，是"你把冲突当成 bug 去修，而它是这个领域的正常形态"。**

三层：

1. **架构层**：你以为"取最新版本"能解决冲突。实测发现**合法双轨**（2022-06-07 前后两套人群走两套规则）——取最新会让一整类人拿到错误答案。条件必须带 `applies_to_cohort` 字段。
2. **数据层**：政策语料**天然没有失效信号**（任何一区政府官网都不标作废），且**1/4 页面没有可靠发布日期**。你要判断"现行有效"，但两个最关键的证据都没有。
3. **评测层**：arXiv 实测证明**检索指标变好不等于端到端变好，语料缺失时更强的检索反而导致更自信的幻觉**。而行业准确率上限 82%（政务一线要求 >90% 且人工复核）。你的系统在"不知道"时必须拒答或追问，但这会让你的准确率数字好看、让面试官问"你什么时候该拒答"。

### 12.3 如果不做这个，替代方向是什么？

1. **重定义而非换方向**——保留语料，把项目从"政策 RAG 问答"改成「**政策条件判定 Agent + 人群分层 + 冲突可解释 + 时效性监控**」。检索退化成 BM25 + 元数据过滤（150 条不需要向量库，这一点写进 README 作为选型理由）。
2. **MVP 只做「安居/住房」**——1 个市级政策 + 13 区变体 ≈ 30-40 条，但计算最复杂、冲突最明显（含 grandfathering 双轨）、有真实房源数字可算到"每月省多少钱"。
3. **真正要换方向的话**——选一个你自己每天在用、数据能无限增长的场景。从业者标准里"我自己每天在用"是唯一无法被质疑的说服力来源，而政策项目你拿不到这句。

### 12.4 三件必须做、且别人都没做的事

GitHub 上 15 个相关政策类项目，**没有一个**做到这三点。这是你的空位：

| # | 要做的事 | 为什么 |
|---|---|---|
| 1 | **判定闭环**：规则基线（纯代码 `check_eligibility`）+ 可解释输出（命中/不命中/**未知** + 依据原文位置）+ 缺失条件主动追问 | 对上掘金帖最难答的第 9 问"检索结果没有证据，系统应该回答还是拒答？" |
| 2 | **自建评测集 ≥50 条，来自真实提问** | CSDN 复盘："初期 50-80 题就够"；"评测问题一定要来自真实用户，否则结果虚高"。15 个公开项目零个有准确率数字 |
| 3 | **冲突/拒答处理**：版本优先级、人群分层、冲突时显式暴露双方证据 | "能提到和业务方协作梳理文档优先级，代表做过真实线上业务，区别纯 Demo" |
