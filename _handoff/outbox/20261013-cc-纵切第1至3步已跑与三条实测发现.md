## 三、🆕 新发现：`bgtwj` 详情页的「有效性」字段是 **JS 模板残渣**

**我抽出元数据块时发现的**（这一步本来只为拿 `发文字号`）：

```python
{'索引号': 'K28044908/2022-17815',
 '发文机构': '武汉市人民政府办公厅',
 '发文字号': '武政办〔2022〕78号',
 '主题分类': '综合政务',
 '成文日期': '2022年06月07日',
 '发布日期': '2022年06月08日',
 '执行时限截至': '2020年12月31日',
 '有效性': '" + Effectivestate + "'}      ← 🔴 JS 模板没渲染
```

**两个问题**：
1. **`有效性` 是前端 JS 动态填的**（`" + Effectivestate + "` 是源码里的字符串拼接残渣）。
   静态抓取拿到的是它，**而且它长得像一个正常的字符串值，不报错**。
2. `执行时限截至 = 2020年12月31日` —— **78 号文是 2022 年印发的**，这个值可疑
   （多半是同一套模板的默认值，未按文件填）。

**影响**：如果将来 `policy_status` 想从页面读「有效性」，**会拿到这种垃圾**。
→ **建议**：`policy_status` 只能由**核实流程**填（SPEC §2.1 的设计是对的），
**绝不能从页面字段读**。这条值得进你的教训清单。
→ 这是本项目「程序不报错但结果是垃圾」的**新形态**：不是抓不到，是**抓到了一个假的真值**。
