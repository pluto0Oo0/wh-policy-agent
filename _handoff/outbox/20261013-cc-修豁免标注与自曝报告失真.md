## 1.2 底层 bug 是真的，且比你描述的更该修

**真实复现**（`data/profile_full.json`：`education="硕士"`, `age=23`）：

```
✅ [符合] 年龄不满45周岁（研究生不受年龄限制）的高校毕业生凭毕业证书在市内落户  ← 因豁免而满足
```

**age=23 < 45 本来就过，豁免什么都没做，却标成"因豁免"。**

**根因（比"字段存在就标"更准）**：原实现是 `exempt_when` **命中就 `return PASS, None, True`**，
**根本不跑正常判定**——不是"懒得判断"，是**没有参照物可判**。

## 1.3 修法

把正常判定抽成 `_eval_normal()`，**先算出正常结论，再拿它当参照**：

```python
normal_status, missing = _eval_normal(profile, cond)

if cond.exempt_when:
    hit = _matches(profile, cond.exempt_when)
    if hit is True and normal_status != PASS:      # ← 只在**翻转了结论**时才算豁免
        return PASS, None, True
return normal_status, missing, False
```

**判据**：豁免只在它把结论从「不是 PASS」翻成「PASS」时才算数。
- 正常就 PASS → 标"因符合"，不标豁免
- 正常 FAIL / UNKNOWN，豁免后才 PASS → 标"因豁免而满足"

**两个设计选择请你看**：

1. **正常判 UNKNOWN 时豁免命中，我算作"豁免起了作用"（标豁免）**。理由：结论从"判不了"变成"符合"是豁免带来的。
2. ⚠️ **但正是这个选择暴露了 F2**（见下）——所以这一条我**现在自己也不确定**，请重点评。
