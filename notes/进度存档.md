### #5 详解：cc-switch 会写 `~/.claude/`，hook 有被覆盖的可能

**10-04 实测**：`cc-switch.exe`（PID 27336）**同时是那个 API 代理**
（`127.0.0.1:15721` 是它在监听），配置里 `sessionAutoSyncEnabled: true`、`skillSyncMethod: auto`。
→ **没有发生过覆盖的证据**（`settings.json` mtime 停在 10-03 16:58），**但机制存在**。

**三条对策（按可靠性排）**：
1. **把项目专用 hook 搬进 `<项目>/.claude/settings.json`** → 跟着项目进 git，可 diff 可回退。
   ⚠️ **不假设它一定生效**：先加一个写标记文件的 hook，**重启一次看标记出没出现**。
2. **把「注册状态」检查加进 `scripts/check_deliver.py`** —— 唯一在 hook 死掉时还能报警的东西
   （wb 指出：hook 检查不了自己有没有被挂载，没注册就不会跑）。
3. `~/.claude/settings.json` 单独建一个极小 git 仓库 → 改动立刻可见为 diff。

**⚠️ 这条同时是「断流」问题的根**：cc-switch 的日志里有
`[ERROR][cc_switch_lib::proxy::providers::streaming] Stream error: error decoding response body`
**共 11 次**（09-27 ×2、10-03 23:53、10-04 00:07、00:55…）。
→ **它做 OpenAI↔Anthropic 格式互转，翻译器崩了整条流就断**，
所以症状是"话说一半"（工具调用块是转换最脆弱的一段）。
**日志**：`~/.cc-switch/logs/cc-switch.log`；**盯现场**：`tail -f` 它。
**可试**：cc-switch 配置里 `enableFailoverToggle: false`（失败转移**是关着的**），或换 provider。
