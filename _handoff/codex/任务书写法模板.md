> **为什么有这份模板**：2026-11-20 出了一次险——T06 任务书里**一个字都没提 worktree / 分支**，
> 而 `AGENTS.md` 里写着「每个任务在独立分支或 worktree 上做」。
> **规则写在 Codex 不读的文件里 = 没有规则。**
> Codex 当时严格按任务书执行，切了分支但**在主工作区里切**——
> 如果它和 CC 同时在主工作区干活，改动会互相污染。

## 一、每个任务书必须包含的 6 个固定段落

### 1. 工作位置（**必须写，不能省**）

```markdown
## 一、工作位置（不许省略）

**在独立 worktree 里干活，不要在主工作区改。**

```bash
cd D:/Claude code/work/wh-policy-agent
git worktree add D:/CodexHome/worktrees/<任务号> -b codex/<日期>-<任务号>
cd D:/CodexHome/worktrees/<任务号>
```

- 主工作区路径：`D:\Claude code\work\wh-policy-agent`（**CC 在这里工作，别碰**）
- 你的 worktree：`D:/CodexHome/worktrees/<任务号>`（**只在这里改**）
- Python 一律用绝对路径：`.venv/Scripts/python.exe`（**worktree 里没有 .venv，用主工作区那个**）
- **不要 commit、不要 push**（合并由审查者做）
- **不要删除 worktree**（红线，需所有者点头）
```

> ⚠️ **`.venv` 的坑**：worktree 是新目录，里面**没有** `.venv`。
> 所有验收命令用 `D:/Claude code/work/wh-policy-agent/.venv/Scripts/python.exe`（**绝对路径**）。
> 但**被测代码要 cd 到 worktree 里**——Python 会从 cwd 找 `src/`，所以：
> ```bash
> cd D:/CodexHome/worktrees/<任务号>
> D:/Claude code/work/wh-policy-agent/.venv/Scripts/python.exe scripts/check_deliver.py
> ```

### 6. 红线 + 完成报告

```markdown
## 六、红线

- 不 commit、不 push、不删除文件
- <本任务特有的红线>
- 任务书没覆盖的情况 → 停机写报告，不许自行扩大范围

## 七、完成报告

`_handoff/codex/reports/<任务号>-完成报告.md`，必须含：
1. 改动文件清单（`git diff --stat HEAD` + `git status --porcelain` 的**真实输出**）
2. 每个文件行数
3. **全部验收命令的完整输出和退出码**
4. **你不确定的地方 / 做的假设 / 没做的事**（如实写，不要藏）
```

## 二、任务书写作的 5 条硬规则

| # | 规则 | 为什么 |
|---|---|---|
| 1 | **工作位置必须写**（worktree 路径 + 绝对路径 python + 别碰主工作区） | 2026-11-20 T06 险情：规则只在 AGENTS.md 里，Codex 不知道 |
| 2 | **验收命令要写绝对路径的 python** | worktree 里没有 `.venv` |
| 3 | **每个验收命令都要写期望输出**（不是只写命令） | 否则 Codex 无法判断「跑出来的算不算对」 |
| 4 | **红线要重复 AGENTS.md 的核心几条** | 任务书是它的行动依据 |
| 5 | **不要写「按 AGENTS.md 执行」就完事**——具体约束要落到文字 | 泛引用 = 不会被执行 |
